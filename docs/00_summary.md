# 00. 제출용 요약 — VC ERP (GP)

> VC 운용사(GP)가 조합 하나를 **기획 → 모집 → 결성 → 운용 → 보고 → 회수·청산**까지 한 시스템에서 처리하는 ERP MVP.
> 데이터는 나중에 LP 시스템이 받아 쓸 수 있는 구조(연동 API + 이벤트)로 남긴다. 개인 연구 목적 프로젝트이며 실제 서비스와 무관하다.

## 1. 한 줄 요약

조합 생애주기 6단계를 **실제 업무 흐름대로 끝까지** 돌릴 수 있고, 돈이 움직이는 모든 기록이 **조합원 원장과 복식부기 분개장에 같은 트랜잭션으로** 남으며, LP에게는 **공개 등급으로 거른 데이터만** API로 나간다.

## 2. 만든 것 (릴리스별)

| 릴리스 | 내용 | 주요 화면 |
|---|---|---|
| R0 | 개발 환경, Neon DB, 데모 로그인 | 로그인 |
| R1 | 조합 기획(규약 버전 1), 출자자 기준 정보, 구성원·운용 인력, 출자 제안(발송·확약·거절) | 조합 · 출자자 · 구성원 |
| R2 | 조합원 명부 확정, 결성총회, 최초 납입, 결성 체크리스트, 등록·관계 기관 | 조합 개요 · 조합원·원장 |
| R3 | 캐피탈콜(약정 비율 자동 배분·납입·미납 관리), 관리보수(투자 기간 전후 기준 분기 계산) | 캐피탈콜 · 관리보수 |
| R4 | 딜 파이프라인(칸반, 단계 조건), 투자 집행(잔액·현금 초과 차단), 포트폴리오·평가, 의무투자 모니터링 | 딜·기업 · 투자 집행 · 포트폴리오 |
| R5 | 정기 보고(월간·분기·반기·연간, 발행 시 스냅샷), 조합원 총회(약정 기준 의결권), 규약 변경(버전 이력) | 총회 · 규약 · 정기 보고 |
| R5.5 | 재무·회계: 기타 비용, 현금출납장, 복식부기 자동 분개, 계정별 원장, 시산표, 재무제표, 결산·기간 잠금 | 현금·비용 · 재무제표 · 장부 · 결산 |
| R6 | 회수(처분손익 분개), 분배 워터폴(초안 → 확정 → 지급), 성과보수, 해산·청산 | 회수 · 분배 · 성과보수 |
| R7 | 대시보드, 통지 화면, LP 연동 API, 이벤트 웹훅 전송, LP 공개 데이터 미리보기, 전 단계 데모 데이터 | 대시보드 · 통지 · LP 연동 |

규모: 마이그레이션 10개, 테이블 37개, 계산용 뷰, GP 내부 API 라우트 86개, LP 연동 API 11개.

## 3. 화면 구조

- **사이드바**: 대시보드 · 조합 · 딜·기업 / 출자자 · 구성원 / LP 연동
- **조합 상세 (큰 탭 5개 + 작은 탭)**
  - 개요: 요약 · 조합 정보
  - 출자자·조합원: 출자 제안 · 조합원·원장 · 캐피탈콜
  - 투자·회수: 투자 집행 · 포트폴리오 · 회수 · 분배
  - 재무·회계: 현금·비용 · 관리보수 · 성과보수 · 재무제표 · 장부 · 결산
  - 총회·보고: 총회 · 규약 · 정기 보고 · 통지

## 4. 데모 순서 (약 10분)

데모 계정으로 로그인하면 샘플 조합 8개가 6단계에 고루 있다.

1. **대시보드** — 전체 약정·납입·투자·분배·NAV, 단계별 조합 수, 확인할 일(미납 캐피탈콜·지급 대기 분배·다음 단계 준비 등), 30일 일정
2. **씨앗 1호 벤처투자조합 (청산 완료)** — 한 조합의 전 과정
   - 조합원·원장: 약정 → 납입 3회 → 분배 4회가 조합원별로 쌓인 원장
   - 회수: IPO·매각·M&A·상환·상각 5건과 처분손익
   - 분배: 최종 분배 상세에서 원금 반환 → 기준수익 → 초과수익·성과보수 워터폴
   - 성과보수: 발생 기준선(납입액 + 기준수익)과 GP 성과보수 4.4억
   - 재무제표·결산: 2018~2025 사업연도 결산 이력, 청산 후 자산 0 = 자본 0
3. **로컬크리에이터 초기투자조합 (운용 중)** — 진행 중인 업무
   - 투자 집행에서 잔액을 넘는 금액 입력 → 차단 (`EXCEEDS_INVESTABLE_AMOUNT`)
   - 분배 만들기: 금액 입력 → 워터폴 계산 → 초안 → 확정(LP 통지) → 지급
   - 통지: 캐피탈콜·총회·분배 통지와 LP별 확인 현황, 일반 공지 작성
4. **모집 중 조합** — 출자 제안 칸반, 명부 확정, 결성 체크리스트
5. **출자자 → LP 공개 데이터 미리보기** — LP 한 곳이 LP 시스템에서 보게 될 데이터(본인 약정·납입·분배, 받은 통지)만 표시
6. **LP 연동** — 이벤트 대기·전송·실패 현황, 지금 전송·재전송

## 5. 설계 원칙

| 원칙 | 구현 |
|---|---|
| 원장은 추가만 (D5) | `ledger_entries`, `journal_entries/lines` 는 DB 트리거로 수정·삭제 차단. 정정은 취소 행·역분개 |
| 계산 값은 저장하지 않음 (D7) | 약정 총액·현금·투자 가능 잔액·포트폴리오는 뷰에서 계산 → 대시보드와 조합 화면 숫자가 항상 같다 |
| 세 겹의 방어선 | 화면 검사 → 서버 업무 규칙(오류 코드 + 규칙 ID) → DB 제약·트리거 |
| 돈이 움직이면 같은 트랜잭션으로 | 업무 기록 + 조합원 원장 + 자동 분개 + 통지 + 연동 이벤트(아웃박스) |
| 동시 처리 | 조합 행 잠금(`for update`), 돈이 움직이는 요청은 `Idempotency-Key` 로 중복 방지 |
| 거래일 기준 현금 | 과거 날짜 출금도 이후 어느 날의 잔액이 음수가 되지 않게 검사 (BR-FIN-02) |
| LP 연동 (D2) | GP DB가 원본. LP 시스템은 API 키 인증 API와 HMAC 서명 웹훅으로 공개 등급(🟢🔵🟡)만 받는다 |

## 6. 단순화한 가정 (⚠️ 실무 확인 필요)

실무 규칙을 확인하기 전까지 단순화한 규칙으로 구현하고, 화면과 문서에 그 사실을 밝혔다. 전체 목록은 [98 실무 확인 목록](98_practice_check.md) (31개).

- 워터폴: 원금 → 기준수익(단리) → 초과수익, GP 캐치업·클로백 없음, 세금 미반영
- 성과보수: 비용이 아닌 이익 분배로 회계 처리
- 관리보수: 투자 기간 중 약정 총액, 이후 투자 잔액 기준
- 총회: 전체 의결권 대비 찬성 비율 하나로 가결 판단
- 회계: 사업연도 1/1~12/31, 투자자산 원가법
- 일부 회수 원금은 GP가 직접 입력

## 7. 기술 스택

Next.js 16 (App Router, Route Handlers), TypeScript, Tailwind CSS, PostgreSQL(Neon) + postgres.js로 SQL 직접 작성, zod 검증, Vercel 배포 전제.

## 8. 실행 방법

```bash
npm install
npm run db:migrate                 # 마이그레이션 001~010
npm run db:seed && npm run db:seed-staff
npm run db:seed-sample             # 출자자·구성원·조합 (기획~결성 준비)
npm run db:seed-sample-deals       # 기업·딜 + 운용 중 조합
npm run db:seed-sample-exits       # 회수·분배
npm run db:seed-sample-lifecycle   # 결성 완료·해산·청산 완료 조합
npm run dev
```

`.env.local` 에 `DATABASE_URL`, LP 연동용 `LP_SYSTEM_API_KEY`, `LP_WEBHOOK_SECRET`, `LP_SYSTEM_WEBHOOK_URL`(비우면 이벤트는 대기)을 둔다.

## 9. 남은 과제 (고도화)

- 회수·분배 정정(취소·역분개), 결산 재개
- LP가 LP 시스템에서 직접 투표
- 이벤트 전송 주기 작업(Vercel Cron), 파일 첨부(규약 원문·보고서 PDF)
- 권한(역할별 메뉴·승인 절차), 감사 로그 화면
