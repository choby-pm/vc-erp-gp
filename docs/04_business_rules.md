# 04. 비즈니스 규칙

> 기준 문서: [01 MVP 범위](01_mvp_scope.md), [02 용어 정의](02_glossary.md), [03 DB 설계](03_db_design.md), [99 결정 기록](99_decisions.md)
>
> 03이 "무엇을 저장하는가"라면, 04는 **"언제, 어떤 조건에서 저장·변경할 수 있는가"**다.
> 여기 적힌 규칙은 서버 코드와 테스트의 기준이 되고, 규칙 ID는 05 API 설계의 오류 코드로 그대로 쓰인다.

> ⚠️ 표시는 실무 규칙을 단순화한 부분이다. 실무 확인 후 바뀔 수 있다.

## 1. 규칙을 지키는 세 겹의 방어선

| 방어선 | 역할 | 예시 |
|---|---|---|
| ① 화면 | 사용자가 실수하기 전에 안내 | 잔액 초과 금액을 입력하면 빨간 안내문 표시, 버튼 비활성화 |
| ② 서버 | **규칙의 실제 판정자.** 여러 테이블을 확인하고 트랜잭션으로 저장 | 잔액 계산 → 초과면 거부 → 통과하면 투자 + 이벤트 함께 저장 |
| ③ DB | 서버에 버그가 있어도 막는 최후 방어선 | 금액 음수 금지, 상태값 제한, 원장 수정 금지 (03 5장) |

화면에서 막았더라도 서버는 **항상 다시 검사**한다. 화면은 우회할 수 있기 때문이다 (API 직접 호출 등).

### 공통 처리 규칙

- **BR-COM-01 트랜잭션**: 돈이나 상태가 바뀌는 작업은 관련된 모든 저장(업무 문서 + 원장 + 통지 + 연동 이벤트)을 **하나의 트랜잭션**으로 묶는다. 하나라도 실패하면 전부 취소된다.
- **BR-COM-02 동시 작업 잠금**: 펀드의 돈이 바뀌는 작업(투자, 캐피탈콜, 관리보수, 분배)은 시작할 때 해당 펀드 행을 잠근다 (`SELECT ... FOR UPDATE`).
  > **왜?** 두 사람이 동시에 잔액 10억 펀드에 각각 7억 투자를 누르면, 둘 다 "잔액 10억"을 보고 통과해 14억이 나갈 수 있다.
  > 잠금을 걸면 두 번째 요청은 첫 번째가 끝날 때까지 기다렸다가 줄어든 잔액(3억)으로 다시 검사받는다.
- **BR-COM-03 확정 후 잠금**: `issued`, `confirmed`, `published`, `sent`, `passed` 처럼 **외부에 알려졌거나 확정된 문서는 수정할 수 없다.** 바꿔야 하면 취소·정정 문서를 새로 만든다.
- **BR-COM-04 작성자 기록**: 사람이 만든 모든 데이터에 `created_by` 를 남긴다.

## 2. 펀드 상태 이동

### 2-1. 상태 이동 조건

```
planning ──① → fundraising ──② → formed ──③ → operating ──④ → dissolved ──⑤ → liquidated
```

| 이동 | 규칙 ID | 조건 (모두 만족해야 함) | 이동할 때 함께 일어나는 일 |
|---|---|---|---|
| ① 기획 → 모집 | BR-FUND-01 | 규약 버전 1의 필수 조건이 모두 입력됨 | 이벤트 `fund.status_changed` |
| ② 모집 → 결성 | BR-FUND-02 | 조합원 명부 확정됨 (3-2) · **약정 총액 ≥ 최소 결성액** (D29) · 결성총회의 결성 안건 **가결** · 최초 캐피탈콜 발송됨 ⚠️ | `formation_date` = 결성총회일, 규약 버전 1 잠금, 이벤트 |
| ③ 결성 → 운용 | BR-FUND-03 | 등록 완료일 입력됨 ⚠️ | 이벤트 |
| ④ 운용 → 해산 | BR-FUND-04 | 해산총회의 해산 안건 **가결** | `dissolution_date` = 해산총회일, 이벤트 |
| ⑤ 해산 → 청산 | BR-FUND-05 | 보유 기업 전부 회수(남은 원금 0) · 최종 분배 `paid` · 현금 잔액 0 · 미마감 캐피탈콜 없음 | `liquidation_date`, 이벤트 |

- **BR-FUND-06 역방향 금지**: 상태는 앞으로만 이동한다. 잘못 이동했다면 되돌리는 대신 관리자 정정 기능(고도화)으로 처리한다.
- **BR-FUND-07 존속 기간 경과 경고**: 만기일이 지났는데 `operating` 이면 대시보드에 경고를 표시한다 (차단은 하지 않음. 실무에서는 총회로 기간을 연장하기도 한다 ⚠️).

## 3. 모집·결성

### 3-1. 출자 제안

- **BR-PROP-01 단계 이동**: `proposed → reviewing → committed` 또는 `→ declined`. `committed`, `declined` 는 되돌릴 수 없다.
  (재협상이 필요하면 거절 후 재제안이 아니라, 결성 전까지는 `committed` 의 확약 금액만 수정 가능)
- **BR-PROP-02 확약 금액**: `committed` 로 바꿀 때 `loc_amount > 0` 이 필수다.
- **BR-PROP-03 발송**: 제안을 발송하면 `proposal` 통지가 해당 LP 한 곳을 수신자로 만들어진다. 펀드 상태가 `fundraising` 일 때만 가능하다.
- **BR-PROP-04 모집 달성률**: `committed` 제안의 확약 금액 합 ÷ 목표 결성액. 100%를 넘어도 막지 않는다 (초과 결성 가능).

### 3-2. 조합원 명부 확정

결성 전 마지막 준비 단계다. **확약(약속)을 약정(법적 금액)으로 바꾸는** 작업이다.

- **BR-MEM-01 대상**: `committed` 상태인 제안만 조합원이 될 수 있다. 확정할 때 LP별 최종 약정액을 입력하며, 기본값은 확약 금액이다.
- **BR-MEM-02 GP 출자 필수**: GP 조합원과 GP 약정액을 반드시 포함한다.
- **BR-MEM-03 GP 의무 출자 비율**: GP 약정액 ÷ 약정 총액 ≥ `gp_commitment_min_ratio`. 미달이면 확정 불가 (`GP_COMMITMENT_BELOW_MIN`).
- **BR-MEM-04 확정 시 함께 저장**: 조합원(`fund_members`) 생성 + 조합원별 `commitment` 원장 행 (`source_type = 'formation'`) + 연동 이벤트
- **BR-MEM-05 확정 후 변경**: 결성총회 가결 전까지는 명부를 취소하고 다시 확정할 수 있다 (원장은 취소 행으로 처리). 결성 이후에는 변경 불가.
- **BR-MEM-06 약정 증액** ⚠️: 결성 이후 약정 증액은 **가결된 규약 변경 안건**이 있을 때만 가능하고, `commitment` 원장 행을 추가한다 (`source_type = 'terms_amendment'`). 감액·신규 조합원 가입·지분 양도는 고도화 단계.
- **BR-MEM-07 1좌 단위**: 조합원 약정액은 1좌 금액의 배수여야 한다 (`COMMITMENT_NOT_UNIT_MULTIPLE`). 명부 확정과 약정 증액 때 검사한다 (R2).

### 3-3. 규약 (버전 관리)

- **BR-TERM-01**: 규약 버전 1은 `planning`, `fundraising` 상태에서만 수정할 수 있다. 결성되면 잠긴다.
- **BR-TERM-02**: 새 버전은 `terms_amendment` 유형의 **가결된** 안건이 있어야 만들 수 있고, 안건 하나당 새 버전 하나다.
- **BR-TERM-03**: 새 버전의 적용일은 해당 총회일 이후여야 한다.
- **BR-TERM-04**: 어떤 날짜에 적용되는 규약 = 적용일이 그 날짜 이전인 버전 중 가장 최신 버전. 모든 계산(관리보수, 분배, 가결 기준)은 이 규칙으로 규약을 찾는다.
- **BR-TERM-05 1좌 금액**: 개인투자조합은 1좌 금액 100만 원 이상 (`INVALID_UNIT_AMOUNT`). 펀드 유형을 바꿀 때도 다시 검사한다.

### 3-4. 최소 결성 기준 (D29)

펀드 유형과 결성 주체에 따라 최소 결성액이 다르다. 기준표는 코드 한 곳(`lib/rules/fund-minimums.ts`)에서 관리하고, 화면 안내와 서버 검사가 같은 표를 쓴다.

| 펀드 유형 | 결성 주체 | 최소 결성액 | 1좌 금액 |
|---|---|---|---|
| 벤처투자조합 | 창업기획자 | 10억 원 | - |
| 벤처투자조합 | 벤처투자회사 · 신기사 · 기타 | 20억 원 | - |
| 개인투자조합 | 전체 | 1억 원 | 100만 원 이상 |
| 신기술사업투자조합 | 전체 | ⚠️ 확인 필요 (검사하지 않음) | - |

> 출처: 사용자 제공 기준 (2026-09-27). ⚠️ 법령 원문 확인 필요 ([98 실무 확인 목록](98_practice_check.md))

- **BR-FUND-09 목표 결성액**: 펀드를 만들거나 수정할 때 목표 결성액 < 최소 결성액이면 저장을 막는다 (`BELOW_MIN_FUND_SIZE`). 처음부터 결성할 수 없는 펀드이기 때문이다.
- **BR-FUND-10 오타 경고**: 목표 결성액이 1조 원을 넘으면 화면에서 확인을 요청한다. 저장은 막지 않는다.
- 결성 시점에는 목표가 아니라 **실제 약정 총액**으로 다시 검사한다 (BR-FUND-02). 법적 요건은 이쪽이다.

## 4. 출자 요청 (캐피탈콜)

### 4-1. 요청 생성

- **BR-CALL-01 요청 가능 상태**: `formed`, `operating`. 단 `fundraising` 에서는 명부 확정 후 **최초 납입(`is_initial = true`)** 만 가능하다 ⚠️.
- **BR-CALL-02 요청 한도**: 전체 요청액 ≤ 펀드의 잔여 약정액 합계 (`CALL_EXCEEDS_UNFUNDED`)
- **BR-CALL-03 조합원별 배분**: 조합원 요청액 = 전체 요청액 × 지분율에서 **원 미만 버림**
- **BR-CALL-04 1원 단위 나머지**: 버림으로 생긴 나머지(전체 요청액 − 조합원별 합계)는 **약정액이 가장 큰 조합원**에게 더한다. 약정액이 같으면 먼저 가입한 조합원에게 더한다. (D13 제안)
  ```
  예) 전체 요청 1억, 조합원 3명 지분율 각 1/3
      33,333,333 × 3 = 99,999,999 → 나머지 1원
      → 약정액이 가장 큰 조합원(동률이면 먼저 가입)에게 +1원 → 33,333,334
  ```
- **BR-CALL-05 조합원별 한도**: 조합원 요청액 ≤ 그 조합원의 잔여 약정액. 나머지 배분 때문에 1원이 넘치는 경우를 막기 위해,
  **"잔여 약정 전액 요청"** 옵션을 선택하면 비율 계산 대신 조합원별 잔여 약정액을 그대로 요청한다 (마지막 캐피탈콜용).
- **BR-CALL-06 날짜**: 납입 기한 ≥ 요청일

### 4-2. 발송과 납입

- **BR-CALL-07 발송**: `draft → issued`. 발송하면 요청이 잠기고(BR-COM-03), `capital_call` 통지가 LP 조합원 전원을 수신자로 만들어진다. GP 조합원에게는 통지를 만들지 않는다.
- **BR-CALL-08 납입 기록**: 조합원별 요청 항목에 대해 `contribution` 원장 행을 추가한다 (`source_type = 'capital_call_item'`). 여러 번 나눠 납입할 수 있다.
- **BR-CALL-09 초과 납입 금지**: 항목별 누적 납입액 ≤ 요청액 (`PAYMENT_EXCEEDS_CALL`)
- **BR-CALL-10 납입일**: 납입일 ≥ 요청일. 미래 날짜는 입력할 수 없다.
- **BR-CALL-11 납입 상태 판정** (뷰에서 계산)
  - 납입액 = 요청액 → `paid`
  - 0 < 납입액 < 요청액 → `partial`
  - 납입액 = 0, 오늘 ≤ 기한 → `pending`
  - 납입액 < 요청액, 오늘 > 기한 → `overdue`
- **BR-CALL-12 마감**: `issued → closed`. 모든 항목이 `paid` 이면 자동 마감한다. 미납이 남아도 GP가 수동으로 마감할 수 있으며, 마감 후에도 미납 조합원의 납입은 기록할 수 있다.
- **BR-CALL-13 미납 조합원 제재** ⚠️: 연체이자, 지분 몰수 등은 규약마다 달라 MVP에서는 **미납 표시와 대시보드 경고만** 한다.

## 5. 딜 파이프라인과 투자

### 5-1. 딜 단계

```
sourcing → reviewing → ic → approved
    │          │   ↑    │
    └──────────┴───┴────┴──→ dropped
               (ic → reviewing: 투심위 보완 요청)
```

- **BR-DEAL-01 허용 이동**: 위 화살표만 허용한다. 단계를 건너뛸 수 없다 (발굴 → 투심위 불가).
- **BR-DEAL-02 종료 상태**: `approved`, `dropped` 는 종료 상태다. 드롭된 기업을 다시 검토하려면 **새 딜을 만든다** (D18 제안). 같은 기업의 과거 딜 이력이 함께 보인다.
- **BR-DEAL-03 드롭 사유 필수**: `dropped` 로 바꿀 때 `drop_reason` 필수
- **BR-DEAL-04 투자 확정 조건**: `approved` 로 바꿀 때 투자 예정 펀드와 예상 금액이 필수다.
- **BR-DEAL-05 이력 기록**: 단계가 바뀔 때마다 `deal_stage_history` 에 한 행을 추가한다.

### 5-2. 투자 집행

- **BR-INV-01 신규 투자 조건**: 펀드 `operating` + 투자일이 **투자 기간 안** (결성일 ~ 결성일 + 투자 기간) + `approved` 딜 필수 + 한 딜에서 신규 투자는 1건만
- **BR-INV-02 후속 투자 조건**: 펀드 `operating` + 같은 펀드가 이미 투자한 기업 + 남은 원금이 0보다 큰 기업(전액 회수되지 않은 기업). 투자 기간이 지나도 허용한다 ⚠️.
- **BR-INV-03 투자 가능 잔액**: 투자 금액 ≤ 약정 총액 − 누적 투자액 − 누적 관리보수 (`EXCEEDS_INVESTABLE_AMOUNT`)
- **BR-INV-04 현금 잔액**: 투자 금액 ≤ 현금 잔액 (`INSUFFICIENT_CASH`, 안내: "캐피탈콜로 먼저 자금을 확보하세요") (D14 제안)
  > **왜 두 가지를 다 검사하나?** 투자 가능 잔액은 "약속된 돈 중 아직 쓸 수 있는 몫"이고, 현금 잔액은 "지금 통장에 있는 돈"이다.
  > 약정은 충분해도 아직 LP에게 돈을 받지 않았으면 투자할 수 없다. 둘 중 하나만 보면 현금이 마이너스가 되는 기록이 생긴다.
- **BR-INV-05 날짜**: 투자일 ≥ 결성일, 미래 날짜 불가
- **BR-INV-06 주목적 비율 경고**: 투자 후 주목적 투자 비율을 다시 계산해, 아래 경우 대시보드에 경고한다 (차단하지 않음)
  - 🟡 주의: 투자 기간이 1년 이내로 남았는데 비율 < 의무 비율
  - 🔴 미달: 투자 기간이 끝났는데 비율 < 의무 비율
  - ⚠️ 주목적 비율의 분모(약정 총액 vs 투자 총액)와 산정 시점은 펀드마다 다를 수 있음

### 5-3. 기업가치 평가

- **BR-VAL-01**: 해당 펀드가 투자한 적이 있는 기업만 평가할 수 있다.
- **BR-VAL-02**: 평가 기준일 ≥ 해당 기업 첫 투자일. 같은 기준일에 중복 평가 불가 (03의 유일 제약).
- **BR-VAL-03**: 전액 회수된 기업은 평가하지 않는다. 대시보드는 **보유 중인 기업의 최신 평가액**만 합산한다. 평가 기록이 없는 기업은 남은 원금을 평가액으로 간주한다.

## 6. 관리보수 ⚠️

실무 규칙이 펀드마다 달라 가장 단순화가 많이 들어간 영역이다. (D16 제안)

- **BR-FEE-01 청구 단위**: 분기 단위로 청구한다. 같은 펀드의 청구 기간은 서로 겹칠 수 없다 (`FEE_PERIOD_OVERLAP`).
- **BR-FEE-02 기간 범위**: 결성일 ≤ 기간 시작, 기간 끝 ≤ 해산일(해산 전이면 만기일)
- **BR-FEE-03 산정 기준**
  - 투자 기간 중: 기준 금액 = **약정 총액**, 요율 = `management_fee_rate`
  - 투자 기간 후: 기준 금액 = **투자 잔액**(누적 투자액 − 회수된 원금), 요율 = `management_fee_rate_after`
  - 기준 금액은 **기간 시작일 시점** 값을 쓴다
- **BR-FEE-04 기간 분할**: 청구 기간이 투자 기간 종료일에 걸치면 두 행으로 나눠 저장한다 (기준이 다르기 때문).
- **BR-FEE-05 계산식**: `보수 = 기준 금액 × 요율 × 기간 일수 ÷ 365` 에서 원 미만 버림. 계산에 쓴 기준 금액, 요율, 기간을 모두 행에 저장한다 (03 설계 의도).
- **BR-FEE-06 현금 확인**: 보수 ≤ 현금 잔액 (`INSUFFICIENT_CASH`)
- **BR-FEE-07 규약 적용**: 요율은 기간 시작일에 적용되는 규약 버전에서 가져온다 (BR-TERM-04).

## 7. 총회와 의결

- **BR-MTG-01 결성총회**: `fundraising` 상태에서 조합원 명부 확정 후에만 열 수 있다. 결성 안건(`formation`)이 반드시 포함된다.
- **BR-MTG-02 해산총회**: 해산 안건(`dissolution`)이 반드시 포함된다.
- **BR-VOTE-01 의결 참여자**: 총회일 기준 해당 펀드의 조합원 전원(GP 포함) ⚠️ 이해관계 안건의 GP 의결권 제한 여부
- **BR-VOTE-02 의결권 스냅샷**: 투표를 기록할 때 그 시점의 지분율을 `voting_power_ratio` 로 저장한다 (D4, 원칙 4).
- **BR-VOTE-03 가결 기준**: 찬성 의결권 합 ≥ 안건의 `quorum_ratio` → `passed`, 아니면 `rejected`.
  **분모는 출석한 조합원이 아니라 전체 의결권**이다 (D17 제안). 기권과 미투표는 찬성으로 세지 않는다.
- **BR-VOTE-04 가결 기준 복사**: 안건을 만들 때 그 시점 규약의 `quorum_ratio` 를 안건에 복사한다. 나중에 규약이 바뀌어도 이미 만든 안건의 기준은 바뀌지 않는다.
- **BR-VOTE-05 결과 확정**: 총회를 `held` 로 바꿀 때 모든 안건의 결과를 판정해 잠근다. 이후 투표 수정 불가.
- **BR-VOTE-06 가결의 효과**

  | 안건 유형 | 가결되면 가능해지는 것 |
  |---|---|
  | `formation` | 펀드 결성 (BR-FUND-02) |
  | `terms_amendment` | 규약 새 버전 추가 (BR-TERM-02), 약정 증액 (BR-MEM-06) |
  | `dissolution` | 펀드 해산 (BR-FUND-04) |
  | `report_approval`, `other` | 상태 변화 없음, 기록만 |

- **BR-MTG-03 소집 통지**: 총회를 만들고 소집하면 `meeting` 통지가 LP 조합원 전원에게 만들어진다.

## 10. 분배와 성과보수 (워터폴) ⚠️

### 10-1. 워터폴 계산 방식 (D15 제안)

실무의 워터폴은 펀드마다 매우 다양하다. MVP는 아래처럼 단순화하고, 단순화한 사실을 화면에도 표시한다.

- **펀드 전체 기준, 누적 계산**: 매 분배 때 "처음부터 지금까지 분배한 총액"을 기준으로 단계를 다시 계산하고, 이전 분배에서 이미 나간 몫을 뺀 만큼을 이번 분배로 한다.
- **기준수익은 단리**: 납입 건마다 `납입액 × 기준수익률 × (분배일 − 납입일) ÷ 365` 를 합산한다.
- **GP 캐치업 없음**: 성과보수는 3단계 초과수익에서만 떼어간다.

```
누적 분배 총액 (이전 분배 + 이번 분배)
│
├─ 1단계 원금 반환 ─── 누적 납입액까지 ──────── 조합원 전원, 지분율대로
│
├─ 2단계 기준수익 ─── 기준수익 금액까지 ─────── 조합원 전원, 지분율대로
│
└─ 3단계 초과수익 ─── 나머지 전부
      ├─ (1 − 성과보수율) → 조합원 전원, 지분율대로
      └─ 성과보수율 ────── GP (carried_interest)
```

```
예) 누적 납입 100억, 기준수익 10억, 성과보수율 20%, 누적 분배 총액 150억
    1단계 원금 반환  100억
    2단계 기준수익    10억
    3단계 초과수익    40억 → 조합원 32억(80%), GP 성과보수 8억(20%)
```

### 10-2. 분배 규칙

- **BR-DIST-01 분배 가능 상태**: `operating`, `dissolved`. 최종 분배(`is_final`)는 `dissolved` 에서만 가능하다.
- **BR-DIST-02 금액 한도**: 분배 가능 금액 ≤ 현금 잔액 (`INSUFFICIENT_CASH`)
- **BR-DIST-03 최종 분배**: 최종 분배의 금액은 현금 잔액과 **정확히 같아야** 한다 (청산 후 펀드에 돈이 남으면 안 됨).
- **BR-DIST-04 계산 저장**: `draft` 에서 워터폴 계산 결과를 조합원 × 단계별로 `distribution_items` 에 저장한다. 조합원별 배분은 BR-CALL-03, 04와 같은 버림·나머지 규칙을 쓴다.
- **BR-DIST-05 확정**: `draft → confirmed`. 잠기고 `distribution` 통지가 LP 조합원 전원에게 만들어진다.
- **BR-DIST-06 지급**: `confirmed → paid`. 조합원별 합계를 `distribution` 원장 행으로 추가한다 (`source_type = 'distribution_item'`). GP의 성과보수도 GP 조합원 원장에 포함된다.
- **BR-DIST-07 과다 분배** ⚠️: 누적 계산에서 이전 분배가 이미 앞 단계 몫을 넘은 경우(예: 이후 추가 납입으로 원금 반환 한도가 늘어남), 그 단계의 이번 분배는 0으로 처리한다. GP 성과보수 반환(클로백)은 고도화 단계.

## 11. 원장

- **BR-LED-01 추가만**: 원장 행은 수정·삭제할 수 없다 (D5). DB 권한과 트리거로도 막는다.
- **BR-LED-02 취소**: 취소 행은 원래 행과 조합원·구분·원인 문서가 같고, 금액은 정확히 반대다. 한 행은 한 번만 취소할 수 있다 (`ALREADY_REVERSED`).
- **BR-LED-03 원인 필수**: 모든 원장 행은 원인 문서(`source_type`, `source_id`)를 가진다. 원인 없이 돈을 기록할 수 없다.
- **BR-LED-04 연동**: 원장 행이 추가될 때마다 `ledger.entry_created` 이벤트를 같은 트랜잭션으로 만든다 (대상 LP = 해당 조합원의 LP).

## 12. 통지와 LP 연동

### 12-1. 통지가 자동으로 만들어지는 경우

| 계기 | 통지 유형 | 수신자 |
|---|---|---|
| 출자 제안 발송 | `proposal` | 해당 LP 1곳 |
| 캐피탈콜 발송 | `capital_call` | LP 조합원 전원 (각자 자기 요청액 포함) |
| 총회 소집 | `meeting` | LP 조합원 전원 |
| 정기 보고 발행 | `report` | LP 조합원 전원 |
| 분배 확정 | `distribution` | LP 조합원 전원 (각자 자기 분배액 포함) |
| GP 수동 작성 | `general` | GP가 선택한 LP |

- **BR-NTC-01 발송 후 잠금**: 발송된 통지는 수정·삭제할 수 없다. 정정이 필요하면 새 통지를 보낸다.
- **BR-NTC-02 확인 기록**: LP 확인 시각은 LP 시스템이 연동 API로 알려줄 때만 기록된다. GP가 직접 입력할 수 없다.

### 12-2. 연동 이벤트

- **BR-EVT-01 같은 트랜잭션**: LP 공개 등급(03 7장)이 🟢, 🔵 인 데이터가 바뀌면 이벤트를 같은 트랜잭션 안에서 만든다 (D12).
- **BR-EVT-02 이벤트 종류**

  | 이벤트 | 계기 |
  |---|---|
  | `fund.status_changed` | 펀드 상태 이동 |
  | `fund.terms_updated` | 규약 새 버전 |
  | `member.joined` | 조합원 명부 확정 |
  | `ledger.entry_created` | 원장 행 추가 (약정·납입·분배·취소) |
  | `notice.sent` | 통지 발송 |
  | `meeting.result_finalized` | 총회 결과 확정 |

- **BR-EVT-03 재전송**: 전송 실패 시 `failed` 로 두고 재시도한다. 5회 연속 실패하면 재시도를 멈추고 대시보드에 표시한다.
- **BR-EVT-04 순서와 중복**: 같은 LP에게 가는 이벤트는 생성 순서대로 보낸다. 받는 쪽(LP 시스템)은 이벤트 ID로 중복을 거른다.
- **BR-EVT-05 🔴 비공개 데이터 차단**: 🔴 등급 테이블의 데이터는 이벤트 `payload` 에 절대 넣지 않는다.

## 14. 이 문서에서 내린 결정 (확정)

아래 결정은 2026-09-27 확정되어 [99 결정 기록](99_decisions.md)에 옮겼다.

- **D13. 1원 단위 나머지 처리**: 원 미만 버림 후 나머지는 **약정액이 가장 큰 조합원**에게 (동률이면 먼저 가입한 조합원).
  - 다른 선택지: 소수점 아래가 큰 순서로 1원씩 나눠주기(최대 잔여 방식, 더 공평하지만 설명이 복잡함) / 항상 GP가 부담
- **D14. 투자 시 현금 잔액도 검사**: 약정 기준 잔액뿐 아니라 현금이 부족해도 투자를 막는다. 캐피탈콜 → 투자 순서를 시스템이 강제한다.
- **D15. 워터폴 단순화**: 펀드 전체 기준 누적 계산, 기준수익 단리, GP 캐치업 없음, 클로백 없음.
- **D16. 관리보수 단순화**: 분기 청구, 일할 계산(365일), 투자 기간 전후로 기준 금액 전환, 경계에 걸치면 기간 분할.
- **D17. 가결 기준**: 출석이 아니라 **전체 의결권 대비** 찬성 비율. 기권·미투표는 찬성이 아니다.
- **D18. 드롭된 딜은 종료**: 다시 검토하려면 새 딜을 만든다. 단계별 소요 기간 분석이 깨끗해진다.
- **D19. 최초 납입은 결성 전 허용**: 명부 확정 후 결성총회 전에 최초 캐피탈콜을 발송할 수 있고, 결성의 조건으로 둔다 ⚠️ 납입 완료까지 요구할지는 실무 확인.
