# 01. MVP 범위 (v3)

> 변경 이력
> - v2: "조합 조성에 필요한 GP 업무 전체" 기준으로 범위 재정의, LP 연동 원칙 추가
> - v3: **청산까지 6단계 전체를 MVP에 포함.** 단, 각 단계는 실제 업무를 가볍게라도
>   처음부터 끝까지 해볼 수 있는 깊이로 만든다. 개발 기간이 늘어나는 것은 감수한다.

## 1. 목표

GP(운용사)가 조합 하나를 **기획 → 모집 → 결성 → 운용 → 보고 → 회수·청산**까지
한 시스템 안에서 실제로 처리해볼 수 있게 한다.
그 과정의 데이터는 **나중에 LP 시스템이 받아 쓸 수 있는 구조**로 남긴다.

## 2. "얇지 않은 기능"의 기준

각 단계는 아래 세 가지를 모두 만족해야 MVP 완료로 본다.

1. **입력 → 처리 → 결과**가 끝까지 이어진다
   (예: 분배금 입력 → LP별 금액 자동 계산 → 분배 통지 발송·기록)
2. **다음 단계가 앞 단계의 데이터를 그대로 이어받는다**
   (예: 결성 때 확정한 약정액이 캐피탈콜 배분, 총회 의결권, 분배 비율의 기준이 된다)
3. **실무에서 막아야 할 실수를 시스템이 막는다**
   (예: 잔액 초과 투자, 약정액 초과 납입 요청, 결성 전 캐피탈콜)

## 3. GP 업무 전체 지도 (전 단계 MVP 포함)

> 국내 벤처투자조합의 일반적인 절차를 기준으로 한 초안이다.
> ⚠️ 표시는 실무 규칙 확인이 필요한 부분이다. 확인 전까지는 단순화한 규칙으로 구현하고, 그 사실을 화면과 문서에 밝힌다.
> 파일 업로드(규약 원문, 제안서 PDF 등)는 전 단계 공통으로 고도화 단계로 미룬다. MVP에서는 파일 대신 핵심 값만 입력한다.

### 단계 1. 조합 기획
- 조합 기본 정보: 조합명, 유형(벤처투자조합 / 신기술사업투자조합), 목표 결성액, 존속 기간, 투자 기간
- 주요 조건: 주목적 투자 분야와 의무 비율, 관리보수율, 성과보수율, 기준수익률, GP 의무 출자 비율 ⚠️
- 조합 상태: 기획 → 모집 중 → 결성 완료 → 운용 중 → 해산 → 청산 완료

### 단계 2. 출자자(LP) 모집
- LP 기준 정보: 기관(정책 출자기관, 연기금, 금융기관, 기업 등) / 개인
- 출자 제안: 제안 → 검토 중 → 확약 → 거절 (통지로 기록)
- 출자확약(LOC) 금액
- 모집 현황: 목표 결성액 대비 확약액 달성률

### 단계 3. 결성
- 조합원 명부 확정: LP별 최종 약정액, GP 출자액, 지분율 자동 계산
- 규약 주요 조건 확정: 단계 1 조건을 결성 시점 값으로 고정 (이후 변경은 총회 의결로만)
- 결성총회: 일자, 의결 결과
- 최초 납입: 결성 시점 납입 요청과 납입 확인
- 등록: 신청일, 완료일 ⚠️ 등록 기관·절차는 조합 유형마다 다름
- 관계 기관: 수탁은행, 사무관리사, 회계감사인

### 단계 4. 운용
- **출자 요청(캐피탈콜)**: 요청 생성 → LP별 요청액 자동 배분(약정 비율) → 통지 → 납입 확인 → 미납 관리
- **딜 파이프라인**: 발굴 → 검토 → 투심위 → 투자 확정 / 드롭, 단계별 메모
- **투자 집행**: 조합·금액·투자 형태(보통주, 우선주 등) 입력, 조합 투자 가능 잔액 자동 차감, 초과 차단
- **포트폴리오**: 투자 기업 목록, 후속 투자, 기업가치(장부가/평가액) 기록
- **관리보수**: 기간별 계산 → 청구 기록 ⚠️ 일반적으로 투자 기간 중에는 약정액 기준, 이후에는 투자 잔액 기준이라 가정
- **의무투자 모니터링**: 주목적 분야 투자 비율 실시간 표시, 기준 미달 경고

### 단계 5. 보고·총회
- **정기 보고**: 조합 현황(약정·납입·투자·평가액) 자동 집계 + GP 코멘트 → LP 공지로 발송
- **조합원 총회**: 안건 등록 → LP별 찬반 입력 → 약정액 기준 의결권 비율 자동 계산 → 가결/부결 기록 ⚠️ 의결 정족수 기준
- **규약 변경**: 총회 가결 안건에 연결해서 조건 변경 이력 기록

### 단계 6. 회수·청산
- **회수**: 회수 형태(매각, IPO, 상환, 상각), 회수 금액, 투자 원금 대비 배수(멀티플) 자동 계산
- **분배**: 분배 가능 금액 입력 → LP별 분배액 자동 계산(지분율) → 분배 통지 → 지급 기록
- **성과보수**: 기준수익률 초과분 계산 ⚠️ 일반적인 구조(원금 반환 → 기준수익률 → 초과수익 중 일정 비율 GP)로 단순화
- **해산·청산**: 해산 결의(총회 안건) → 잔여 자산 처리 → 최종 분배 → 청산 완료

## 4. LP 시스템 연동 설계 원칙

1. **출자자는 독립된 기준 정보로 만든다**
   한 LP가 여러 조합에 출자해도 같은 LP로 묶이고, 나중에 LP 시스템 계정과 1:1로 연결된다.
2. **LP와 관련된 돈의 흐름은 전부 원장(기록 목록)으로 남긴다**
   약정, 납입 요청, 납입, 분배를 LP 단위로 한 줄씩 기록한다. 금액은 덮어쓰지 않고 쌓는다.
3. **데이터마다 LP 공개 여부를 구분한다**
   - LP 공개: 조합 정보, 본인 약정·납입·분배, 통지, 보고, 총회 안건
   - GP 내부 전용: 딜 파이프라인, 투심위 메모, 다른 LP의 정보
4. **GP → LP로 가는 모든 요청은 '통지' 단위로 기록한다**
   출자 제안, 캐피탈콜, 보고, 총회 소집, 분배를 발송 상태(작성 → 발송 → 확인)와 함께 저장한다.
5. **LP 시스템은 DB를 분리하고 API로 연동한다** (D2 확정, [결정 기록](99_decisions.md) 참고)
   GP DB가 원본이다. LP 시스템은 자기 DB에 LP 전용 데이터(계정, 읽음 여부 등)를 두고,
   GP 데이터는 GP가 제공하는 연동 API와 이벤트 알림으로 받아간다.

## 5. 개발 순서 (릴리스)

조합 생애주기 순서대로 쌓는다. 각 릴리스가 끝나면 그 단계까지 실제로 돌려볼 수 있다.

- **R0** 개발 환경, DB 연결, 데모 로그인
- **R1** 조합 기획 + LP 모집
- **R2** 결성 + 최초 납입
- **R3** 캐피탈콜 + 관리보수
- **R4** 딜 파이프라인 + 투자 집행 + 포트폴리오 + 의무투자 모니터링
- **R5** 정기 보고 + 조합원 총회 + 규약 변경
- **R5.5** 재무·회계: 기타 비용, 현금출납장, 복식부기 분개장(업무 기록 자동 분개), 계정별 원장, 시산표, 재무상태표·손익계산서, 결산 (D34, D35 — 조합 운영에 회계 처리는 필수라 추가)
- **R6** 회수 + 분배 + 성과보수 + 해산·청산 (회수·분배도 자동 분개, D37)
- **R7** 대시보드 정리, 데모 데이터, 제출용 요약

## 6. 성공 기준

데모 조합 하나로 아래 시나리오를 처음부터 끝까지 막힘없이 진행할 수 있다.

1. 조합을 기획하고 LP 3곳에 제안 → 2곳 확약 → 결성총회 → 결성 완료
2. 캐피탈콜 시 LP별 요청액이 약정 비율로 자동 계산되고, 1곳 미납 상태가 구분된다
3. 딜을 투자 확정까지 옮기고 투자 집행 → 조합 잔액 감소, 잔액 초과 금액은 차단된다
4. 정기 보고를 발송하고, 총회 안건이 약정액 기준 의결권으로 가결된다
5. 투자 기업을 회수 → LP별 분배액과 성과보수가 계산된다 → 해산·청산 완료
6. 모든 단계의 숫자가 대시보드와 일치하고, LP 한 곳 기준으로 공개 데이터만 조회된다
